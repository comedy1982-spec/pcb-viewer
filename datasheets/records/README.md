# 데이터시트 레코드 (원본)

부품마다 한 파일(`<부품번호>.json`)로 데이터시트의 핵심을 **구조화해서** 저장합니다. 이 폴더가 원본이고,
`datasheets/db/*.html`과 `src/parts/dsdb.js`·`src/parts/dskey.js`는 여기서 만들어지는 결과물입니다.
**페이지(.html)가 아니라 레코드(.json)를 고치세요.** 페이지를 고쳐도 다음 빌드 때 덮어써집니다.

```
node scripts/dsdb.mjs          # 검사 → datasheets/db/*.html 생성 → dsdb.js · dskey.js · db/index.json 번들 (npm run build가 먼저 실행)
node scripts/dsdb.mjs --init   # parts.js에 있는 부품 중 레코드가 없는 것을 stub 레코드로 생성
```

## 형식 (스키마: `src/parts/dsrec.js`)

```jsonc
{
 "mpn": "LTC4359",                 // 보드·BOM의 mpn과 같아야 연결됨. 파일 이름 = mpn의 영숫자.+- 외 문자를 _로
 "alias": ["RC0402FR-07*L"],       // (선택) 같은 데이터시트를 쓰는 주문 코드 패턴, * 와일드카드
 "mfr": "Analog Devices", "cat": "전원", "price": 2.4, "title": "…",
 "status": "done",                 // stub(초안) · done(원문으로 작성) · verified(독립 재확인)
 "verify": {"date": "2026-10-29", "by": "…", "note": "…"},   // verified일 때 필수
 "src": ["https://…pdf"],          // 실제로 읽은 문서
 "meta": ["제조사 · 분류 · 한 줄 설명", "원본: <a …>"],        // 제목 아래 줄 (HTML 허용)
 "todo": "아직 빠진 항목",           // (선택) 노란 칸
 "issues": [{"p": "문제", "fix": "제안", "url": "근거"}],      // (선택) 알려진 문제 — 페이지 위 빨간 칸
 "key": {                          // (선택) 회로 생성기가 부품을 고를 때 쓰는 값 — partrank.js에는 더 이상 적지 않음
   "mpn": "LM111733QDCYRQ1",       //   후보 번호가 레코드 mpn과 다를 때(계열 페이지)
   "spec": {"i": 20, "vin": [4, 80], "vout": 3.3, "v": 75, "pkg": "MSOP-8", "adj": 1, "sync": 0},
   "grade": "Q100", "ext": ["인덕터"],
   "basis": "데이터시트 숫자가 아닌 설계 선택일 때 근거"  //   있으면 교차 검사를 건너뜀
 },
 "sections": [                     // 페이지 본문
   {"h": "핵심 사양", "blocks": [{"dl": [["기능", "…"], ["전원", "4–80 V"]]}]},
   {"h": "절대 최대 정격", "blocks": [{"table": {"head": ["항목","최소","최대","단위","비고"], "rows": [["VIN","-28","100","V",""]]}}]},
   {"h": "설계 메모", "blocks": [{"html": "<ul><li>…</li></ul>"}]}
 ]
}
```

- 값은 데이터시트에 적힌 단위 그대로 씁니다. 모르는 값은 비워 두거나 "데이터시트 확인 필요" — 기억으로 채우지 않습니다.
- 표의 첫 칸이 `핀`·`번호`인 표는 핀 표로 봅니다. 숫자가 아닌 행(그룹 설명, "—")은 핀 번호 검사에서 빠집니다.
- 스크립트·이미지는 넣지 않습니다. 원문 단락을 복사하지 않고 요약·표만 씁니다(저작권).

## 빌드 때 검사

오류(빌드 중단): status 값, verified인데 verify.date 없음, 가격이 숫자가 아님, 절대 최대 정격·권장 동작 조건에서 최소 > 최대,
핀 표의 핀 번호 중복, key.spec.vin이 [최소, 최대]가 아님, JSON 문법.

경고: done인데 src 없음, 표 칸 수 불일치, key.spec의 전류(i)·전압(v)·패키지(pkg)가 페이지의 핵심 사양·절대 최대 정격·패키지
항목에 없음 (`basis`가 있으면 생략). 이 교차 검사로 생성기 값과 데이터시트가 어긋난 곳(예: L9908 TQFP-64 → 실제 TQFP-48)을 찾습니다.

알려진 문제는 빨간 칸, 생성기 기준값은 제목 아래 한 줄로 보입니다.
